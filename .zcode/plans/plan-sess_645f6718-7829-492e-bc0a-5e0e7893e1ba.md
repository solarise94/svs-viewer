# AI 读片助手迁移到 pi（earendil-works/pi）架构升级方案

## 目标架构

```
浏览器 ──► Flask(gunicorn, 鉴权/切片/标注库/配置) ──代理 /api/ai/*──► Node sidecar (pi agent)
              ▲                                                            │
              └──────── internal 回调（取图/落标注/spot 增量）◄────────────┘
```

- **Flask 保留**：管理员鉴权、切片服务（OpenSlide/坐标刻度尺）、share_store 标注库（effect_key 幂等留在 Python）、ai_config.json 配置存储（Fernet 加密不变）、前端静态资源。
- **Node 22 + TypeScript sidecar**（新目录 `sidecar/`）：以 npm 包 `@earendil-works/pi-ai@0.84.0` + `@earendil-works/pi-agent-core@0.84.0`（锁版本）为引擎，承载 agent loop、6 个领域工具、会话持久化、compaction、SSE。只监听 127.0.0.1。
- **前端零改动**：/api/ai/* 端点、SSE 事件名与 payload、transcript schema、X-AI-Session-ID、after_seq/event_reset 协议逐字段保持。
- 探查确认：pi 的 `AgentHarness` 是桩不可用，用底层 `Agent` 类 + 自己挂接 compaction（照 coding-agent 的 agent-session.ts 模式）；pi 包已发布 npm，Node≥22.19，不依赖 bun。

## 实施步骤

### Step 0 · 风险最高最先验证：cpa 兼容性 spike（glm-coder）
- `sidecar/` 脚手架（package.json 锁 pi 0.84.0、tsconfig、vitest）。
- `pi-model.ts`：从 config（base_url/api_key/model/max_tokens/context_window_tokens/api_protocol）构造 pi `Model<"openai-completions">`；cpa 中转 compat 覆盖：`supportsStore:false, supportsDeveloperRole:false, supportsStrictMode:false, maxTokensField:"max_tokens", supportsReasoningEffort:false`；api_protocol=anthropic 时走 pi 的 anthropic-messages api 类型。
- 最小脚本：一次带工具的流式调用打真实 cpa gemini-3.6-flash，验证 tool_calls/usage/流式增量是否透传。**验证不过则立刻上报，不继续后面步骤。**

### Step 1 · 会话存储 + 事件日志（glm-coder）
- `session-store.ts`：沿用 `SHARE_DATA_DIR/ai_sessions/` 布局与权限（目录 0700/文件 0600）：`<id>.json`（id/slide/kind/annotation_id/title/status/agent_state/observations/pending_snapshot_review/spot_cursor/timestamps/archived 等现有字段）+ `<id>.events.jsonl`（`{type,payload,ts,seq}` 同格式）+ `index.json`。消息以 pi AgentMessage 形态存储，落盘时图片替换为 image_ref 占位（含 src/magnification/slide_fingerprint）。
- 单进程 Node 简化并发模型：进程内互斥 + status CAS，废弃 lease/fencing/WAL 多进程机制（effect_key 幂等仍由 share_store 保证）。文档记录此简化。

### Step 2 · 领域工具 + Flask internal 回调（glm-coder）
- Flask 新增 `/internal/ai/*`（共享 token `AI_INTERNAL_TOKEN` 鉴权）：`region`（复用 `_read_region_b64`+青色坐标刻度尺）、`annotate`（→ share_store.add_roi，effect_key 幂等、source="ai"）、`spots`（list_changes/current_change_seq）、`slide_info`（宽高/level_downsamples/mpp/指纹）。
- sidecar `tools.ts`：6 个 pi AgentTool（typebox schema），坐标语义原样移植——level-0 像素、goto ±2 层 clamp、viewportPx=1024、`base=10/mpp` 倍率表、95% 概览容差、1568/4096 取图尺寸、pending-snapshot 守卫（未消化禁止 goto/snapshot）、fork 会话无 create_annotation、no_annotation 必须带 reason。snapshot 返回 `{type:"image", data, mimeType}`。

### Step 3 · Agent loop + SSE 事件适配（glm-coder）
- `agent-runner.ts`：pi Agent 封装——system prompt（中文 prompt 原样移植）、make_main_messages/make_fork_messages 等价逻辑、steering（continue/ask 注入）、abort（cancel）、agent_retrying 退避。
- `events.ts`：pi AgentEvent → 现有 SSE 事件名/payload 逐项映射（agent_thinking/text_delta/tool_started/snapshot_captured/observation/annotation_created/snapshot_reviewed/agent_paused/agent_finished/agent_error/agent_retrying/slide_opened/session_resumed/fork_created/fork_resumed/session_ended/event_reset）。
- `transcript.ts`：pi 消息 → 前端 canonical 形态（role/content/tool_calls/tool_call_id/image_ref/display_text/spot_updated 标记）。

### Step 4 · compaction + 图片淘汰（glm-coder）
- 挂接 pi 的 `shouldCompact/prepareCompaction/compact`（每 turn 后判断，reserveTokens/keepRecentTokens 取自 config），LLM 结构化摘要写回会话（解决"压缩后失忆"）；摘要请求隔离（pi 自带 cacheRetention:none）。
- `transform-context.ts`：pi `transformContext` 钩子实现图片淘汰——只保留最近 N 张快照（默认 6，config 可调），首张全片概览永远保留，旧图换文本占位符；session 恢复时 image_ref 经 Flask region 重新物化（指纹不符降级文本）。

### Step 5 · Flask 代理层 + 删除旧引擎（glm-coder）
- /api/ai/run|continue|ask|cancel|sessions|session/:id|archive|stream 改为鉴权后代理到 sidecar（SSE 流式透传、X-AI-Session-ID 头透传）；/api/ai/config 保持 Flask 本地存储。
- 删除 ai_agent.py、ai_session.py、ai_protocol.py 及对应测试文件中专测删除模块的部分；改写 test_ai_flow.py 为代理层测试（mock sidecar）。

### Step 6 · sidecar 测试 + 部署（glm-coder 实现，我执行验证）
- vitest：坐标语义、工具守卫、compaction 挂接（mock streamFn）、transformContext 淘汰、session store、事件契约 golden 测试。
- Containerfile 多阶段：node:22 阶段构建 sidecar（npm ci + tsgo），python:3.12-slim 终段拷贝 node 运行时 + sidecar dist；entrypoint 先起 sidecar 再起 gunicorn；新增 env AI_SIDECAR_PORT/AI_INTERNAL_TOKEN。
- docs/ai-session-architecture.md 重写为新架构。
- README 补本地开发说明（npm install + 起 sidecar）。

### Step 7 · 验收（我 + 用户）
- 我：跑全部测试 → 本地起 Flask+sidecar，mock 模型 + （若 key 可用）真实 cpa smoke → 容器构建验证。
- 用户：真实页面验收（读片全流程、快照跳转、标注、fork 对话、断线恢复）。

## 关键风险与对策

1. **cpa 中转不透传 usage/tool_calls** → Step 0 最先验证；usage 缺失时 pi 本地估算兜底（1200 tok/图），不会失控。
2. **pi 是年轻项目** → 锁 0.84.0 + package-lock；不追新。
3. **崩溃恢复语义变化**（多进程 fencing → 单进程）→ 单容器单 sidecar 下本来就不需要；status 卡在 running 的会话恢复时自动转 paused 可 continue。
4. **旧会话数据不迁移**（文件留盘不读）；旧 Python 代码迁移后删除（git 历史可找回）。
